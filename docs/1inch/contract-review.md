# Contract and deployment readiness review

Reviewed on 2026-09-13. Scope: `PositionAccount`, `PositionFactory`, `UniswapInventoryAdapter`, `CycleAccounting`, `TokenOps`, protocol interfaces, owner launch preflight, and the local Rabby deployment boundary. This is an engineering review with automated and fork evidence, not an external audit or formal verification certificate.

## Result and changes

No contract fund-theft issue was established within this review's scope. The Solidity implementation and its deployment bytecode are unchanged. An availability defect in the frontend recovery path was reproduced and fixed; Solidity regression tests confirm the underlying owner recovery paths. Remaining external dependency and economic limits are listed below, rather than represented as completed guarantees.

| ID  | Severity / disposition                   | Finding and result                                                                                                                                                                                                                                                                                                                                                                 |
| --- | ---------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| R1  | Medium · fixed                           | An Aave `healthFactor()` read failure rejected the entire launch snapshot, hiding owner defense, repayment and debt-free exit. Only that getter may now return `null`; ownership, phase, debt, balances, allowances and deployment checks remain mandatory. Open/convert/ship fail closed; recovery still simulates the exact transaction.                                         |
| D1  | Medium · fixed during review             | A stale deployment tab could sign a newer review returned by the local server. Immutable review IDs now bind every operation; the browser compares the complete returned review to the displayed review before invoking Rabby.                                                                                                                                                     |
| D2  | Medium · fixed during review             | A second deployment process could rewrite the active journal before failing to bind the port. The server now acquires the fixed loopback port before reading or writing the deployment journal.                                                                                                                                                                                    |
| D3  | Medium · fixed during review             | The deployment journal identity initially covered only factory bytecode. It now commits both creation bytecodes and the constructor configuration, preventing an adapter-only build change from silently reusing an old completion state.                                                                                                                                          |
| D4  | Medium · fixed during review             | A stale tab could erase the shared recovery hash before server review validation. Hashes are now keyed by review ID; the storage capability probe uses a separate key and existing evidence blocks another signature.                                                                                                                                                              |
| L1  | Medium · open dependency limit           | There is no independent underlying price-feed age check or Arbitrum sequencer recovery grace guard inside Noria's contracts. A fresh RPC block is not proof that a price source is fresh. Aave enforces its current borrowing/health rules; shipment itself is not a new borrow. Do not describe HF as a guaranteed timely liquidation defense.                                    |
| L2  | Informational · explicit trust boundary  | Aave, its receipt/debt tokens and USDC depend on upgradeable protocol infrastructure. The app checks canonical addresses and reserve bindings; this is not implementation-hash pinning across all proxy dependencies. The adapter/router and Aqua/SwapVM identities are checked separately.                                                                                        |
| L3  | Informational · explicit owner authority | The owner authorizes the SwapVM program and inventory provenance. Solidity validates the order envelope, maker-only traits and tracked inventory; it does not prove every supplied opcode implements the intended strategy. The normal frontend independently reconstructs the official SDK program. An owner bypassing it can authorize a harmful strategy for their own account. |
| L4  | Informational · product scope            | No unattended keeper, public taker credential, automatic aggregator admission, gas-reserve obligation lifecycle, or UI profit-attestation/allocate-cycle automation is delivered by deployment. Nonzero provisions remain rejected.                                                                                                                                                |

An independent source reviewer examined the deployment assistant and nullable-health boundary, identified D1–D4, and confirmed their closure after the fixes. A second reviewer resumed the earlier rate-limited contract pass and found no additional established exploitable defect in the remaining contract paths. That bounded source review confirmed that removing Noria’s avoidable health getter prerequisite does not remove Aave’s own repayment, withdrawal, token or oracle dependencies. Neither review is an external audit or a formal proof. Automated and fork evidence was executed separately by the implementation agent.

## Contract properties checked

| Component               | Checks and practical boundary                                                                                                                                                                                                                                                                                  |
| ----------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Factory                 | Constructor-fixed protocols, no admin/setters/upgrades, unique owner-scoped IDs, correct receipt/debt assets and Aave binding, owner/keeper both set to caller, registration, no funds moved at account creation. Runtime size is checked against EIP-170.                                                     |
| Account access/state    | Owner-only borrowing, conversion, program authorization, provenance, allocation and exit; keeper can stop and conditionally defend, not withdraw/attest/trade. Reentrancy guards cover state-changing token/protocol paths. Invalid phases and unsafe HF boundaries revert atomically.                         |
| Liquidity and approvals | Tracked inventory cannot silently expand from donations. Only one strategy is active; Aqua virtual balances cap it. Active Aqua allowances are intentionally broad for bidirectional fills and revoked when docked/defended. Fixed adapter/pair and bounded minimum output/deadline prevent arbitrary routing. |
| Inventory provenance    | Public Aqua pushes and wallet donations do not establish profit. Owner checkpoint binds cycle, nonce and dock snapshot; confirmations cannot replay or exceed the docked inventory. Provenance remains an owner attestation backed by the external journal.                                                    |
| Debt/accounting         | Scaled-debt checkpoints detect outside debt movement; reconciliation bounds external reduction and carries accrued interest without inventing LP earnings. Prior losses precede surplus splitting; repayment caps at actual debt. Zero debt does not automatically trigger another LP cycle.                   |
| Adapter                 | Exact input consumed; minimum output checked against recipient balance delta, not an untrusted router return; previous dust separated; approvals reset; foreign pairs, expired quotes and reentrancy rejected.                                                                                                 |
| Recovery/exit           | Owner defense can stop and repay without a health read. WETH realization and external repayment remain owner controlled. Exit requires debt zero and stopped phase; a failed Aave withdrawal rolls the whole exit back. Aave itself can still be unavailable.                                                  |
| Token operations        | Contract code required; handles ERC20 true/no-return conventions, clears prior approvals before resetting, rejects failed/malformed calls. Scope is official WETH/native USDC/Aave tokens, not arbitrary fee-on-transfer assets.                                                                               |

## Evidence and reproducibility

- `forge test --root integrations/aqua/contracts`: **66 passing tests**, including 256-run fuzz properties, owner recovery during health-read failure, and new-exposure rejection.
- `npm run aqua:artifacts`: recompiles and compares the committed factory/adapter artifacts, Solidity 0.8.30, Cancun, optimizer 200. Factory runtime: **22,889 / 24,576 bytes**.
- `npm run validate:aqua-deployment`: both exact creation transactions and runtime checks passed on a new owned fork using the public deployment-wallet address with artificial local funds. No Rabby signature or public deployment was made.
- `npm run validate:aqua-launch`: current Graph plans and both collateral choices passed the same prepare/verify lifecycle used by the frontend, including stop, repayment and exit. Reports record operation-by-operation effects.
- `npm run --workspace @noria/aqua fork:rehearse`: official Aave/Aqua/SwapVM execution, taker access rejection, bidirectional related-party fills, cycle accounting and terminal exit. The reviewed run checked **32 transactions and 11 assertions**, with terminal debt zero, revoked Aqua approvals and no stranded inventory.
- Node and browser regression tests cover exact receipt identity, stale-tab payload substitution, wrong wallet, ambiguous wallet outcome, preservation of recovery hashes and responsive deployment layout. Local Rabby providers in browser tests are explicit fixtures.

The fork validates token transfers and protocol compatibility at its recorded block. It does not prove future oracle availability, external demand, public access credentials, profitable economics, real Privy confirmation or Ethereum settlement finality. Rehearsal funding, access-token minting and account impersonation are classified as local fixtures. The public frontend must remain `deployment-required` until the real verified factory address is configured.

## Deployment acceptance

Use the [beginner Rabby guide in Portuguese](deploy-and-test.pt-BR.md). Preserve the commit, both public deployment receipts, source verification, runtime identities, environment configuration and owner lifecycle report. Do not claim public deployment or live Privy funding from local output. A later change to protocol dependencies, compiler settings, program construction or contract source needs a new review and matching artifacts before signing.
